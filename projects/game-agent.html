遊戲代理

讓 AI 在背景代打一款回合制自走棋類遊戲，不占用螢幕。重點是不把截圖直接丟給語言模型，而是先用畫面辨識把畫面變成精簡的狀態。

  • Python
  • MCP
  • RapidOCR
  • OpenCV
  • ONNX
  • Win32
  • LLM Agent

以 Claude Code、Codex 等 AI 代理協作開發：需求、架構與技術選擇、實驗設計與結果判讀由本人與 AI 討論後決定，程式碼主要由 AI 撰寫。

0.47 秒

全畫面 OCR（原本 18～25 秒）

約 106 ms

備戰畫面的狀態查詢

約 300 張

飛行紀錄器保留的最近畫面

動機

純截圖交給模型，一回合大約要 1.5 萬 token。我的目標是降到約 1,000 token：模型拿到的是整理好的 JSON 狀態，只負責判斷下一步。

每一局都會記錄花費與回合數，方便比較不同作法。

架構

動作不是一步一問，而是成串送出，代理 API 每一步都驗證畫面是否如預期。

畫面辨識

頭像模型用 MobileNetV3-small 取 embedding，再和 gallery 比對，以 ONNX 在 CPU 上推論。校準集沒有達到門檻時就拒識，不硬猜。

飛行紀錄器保留最近約 300 張畫面，辨識出錯的畫面會另外存下來，供之後離線重放。

量測

全畫面 OCR 耗時

修正前18～25 秒
修正後0.47 秒

慢的原因不在辨識本身：排程啟動的程序被系統降了優先序並節流。另外，備戰畫面的狀態查詢約 106 ms。

試過但沒採用：本地視覺模型

讓本地視覺模型直接讀畫面，文字和數字全對，但座標偏了 200～300 像素、角色全部認錯，所以只當備援。

目前的限制

  • 實際打一局仍然要看約 100 張圖，還沒達到 token 目標。
  • 解析度不一致時，固定座標會失準。
  • 頭像模型還沒做實機驗收。
  • 免費模型的判斷力有限。
